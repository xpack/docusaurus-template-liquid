## Obtain project sources

The project is hosted on GitHub:

- https://github.com/{{githubProjectOrganization}}/{{githubProjectName}}.git

<BranchesDetails />

To contribute **Pull Requests**, fork the project and make sure the
**Copy the {{branchMain}} branch only** option is **disabled**, so that
the `{{branchDevelopment}}` branch is also copied and can be used for
contributions.

:::tip

After making changes, direct the Pull Requests to the
`{{branchDevelopment}}` branch.

:::

The next step would normally be to **clone the forked repository**.

However, if Pull Requests are not intended, directly clone the
`{{branchDevelopment}}` branch of the original repository:

```sh
rm -rf ~/Work/{{githubProjectOrganization}}/{{githubProjectName}}.git && \
mkdir -p ~/Work/{{githubProjectOrganization}} && \
git clone \
  --branch {{branchDevelopment}} \
  https://github.com/{{githubProjectOrganization}}/{{githubProjectName}}.git \
  ~/Work/{{githubProjectOrganization}}/{{githubProjectName}}.git
```

If the repository has already been cloned, update it with:

```sh
git -C ~/Work/{{githubProjectOrganization}}/{{githubProjectName}}.git pull
```

By default, to prevent inadvertent changes, xpm dependencies are
installed in read-only folders with filtered content; developer-related
files are not installed

However, during development, it is convenient to maintain a writable
instance of the code to enable changes in parallel with the parent
project.

Therefore, during development, if this project is used as a dependency
of another project, it is convenient to use the full version of the
project and make changes directly in the local development folder.

The mechanism xpm uses for this is called _linking_, and is similar
to the npm link mechanism.

The process has two steps:

1. Tell the global xpm configuration where the local development
   folder is located.
2. Tell the top project to use the linked development folder
   instead of the installed read-only dependency.

The first step requires executing the `xpm link` command in the
local development folder, as shown below:

```sh
xpm link -C ~/Work/{{githubProjectOrganization}}/{{githubProjectName}}.git
```

The result is the creation of a symbolic link in the global xPacks
store pointing to the local development folder.

For example:

```console
% ls -l xPacks/{{githubProjectOrganization}}/{{githubProjectName}}/.link
lrwxr-xr-x  1 ilg  staff  75 Oct 26 21:57 xPacks/{{githubProjectOrganization}}/{{githubProjectName}}/.link -> /Users/ilg/Work/{{githubProjectOrganization}}/{{githubProjectName}}.git
```

For the second step, in the top project, instead of adding the
dependency by installing it, run the command to link it:

```sh
xpm link {{packageScopedName}}
```
